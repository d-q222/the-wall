Backs the pitch claim "tuned small owned model vs its own base, at what cost vs
frontier" with measured numbers for the frontier side. The River side is
unmeasured — see Caveats.

## Method

1. Pricing for `claude-sonnet-5` came from the `claude-api` skill, not memory,
   per the task brief.
2. `measure.py` builds 20 synthetic `JudgeRequest`-shaped cases
   (`{current, protected, draft}`) from the three fixture matters in
   `fixtures/matters/` (chen, delmarva, reyes) — never opens
   `/Users/dqi26/the-wall/data/`. Per matter: 2 clean drafts (own facts only)
   and 6 leak drafts (one other matter's name+amount, distinctive detail, or
   org, for each of the two other matters) = 8 per matter × 3 matters = 24,
   truncated to the first 20.
3. For each case, `measure.py` calls `claude-sonnet-5` through the `anthropic`
   Python SDK with the `anthropic-workspace-id` header (from
   `/Users/dqi26/the-wall/.env`), timing the call with `time.monotonic()` and
   reading `response.usage.{input,output}_tokens` for real token counts.
4. Cost per call = `input_tokens/1e6 * $2.00 + output_tokens/1e6 * $10.00`.
   Cost per 1,000 judgments = mean cost per call × 1,000.
5. Latency and token percentiles use linear-interpolation p50/p95 over the 20
   calls.

Run it yourself: `uv run python evals/cost/measure.py` (needs
`ANTHROPIC_API_KEY` and `ANTHROPIC_WORKSPACE_ID` in
`/Users/dqi26/the-wall/.env`; writes `evals/cost/results.json`).

## River judge: not measured

The task brief says to also measure the River judge "if b2-river has a
deployment or sampling path on main." As of this measurement:

- `main` and the `b2-river` branch both carry only `river/.gitkeep` — no
  render script, no SFT launch, no `wall/judge.py` implementation
  (`wall/judge.py` on `main` is still the stub that raises
  `NotImplementedError`).
- The River SDK's dedicated-inference path (`create_deployment`, serving a
  checkpoint behind an OpenAI-compatible URL) is a **gated feature** per the
  `river-client-training` skill — it requires River to grant deployment access
  to the team and base model first, and there's no evidence that happened
  tonight.

There was nothing runnable to time or price, so the River row above is blank
rather than guessed, per the task's own instruction ("Numbers you did not
measure stay blank").

## Caveats

- n = 20 is small; these are point estimates, not confidence intervals, and
  the cases are self-written synthetic drafts (short letters, not real
  filings), so absolute token counts will differ from production drafts —
  treat the **cost-per-judgment ratio** as the transferable number, not the
  raw token counts.
- One `claude-sonnet-5` call per case, sequential, no prompt caching — a
  production judge that caches the protected-facts context across calls in
  the same matter would cost less per call after the first.
- Latency is wall-clock for a single sequential call from this machine to the
  API over the demo network; it does not reflect a warmed connection pool or
  concurrent load.
- Pricing is Anthropic's first-party API rate as read on 2026-09-27; it is not
  guaranteed stable and this file will go stale if it isn't re-measured.
- This measures the **prompt judge's** cost, which is FR-7 (the fallback
  detector), not River's tuned judge (FR-9) — the pitch's "cost vs frontier"
  claim needs the River side filled in before it can be made honestly.
